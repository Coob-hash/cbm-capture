CBM is styled as a digital field instrument, not a SaaS dashboard. The identity is built from site-documentation cues used functionally, never decoratively: (1) a concrete/paper neutral base with ink + steel structural colors; (2) hi-vis signal colors reserved strictly for semantics — orange = work/action, amber = awaiting decision, red = escalated/critical, green = verified/closed, blueprint blue = in-flow; (3) an engineering title-block motif — stencil uppercase micro-labels with hairline rules, squared 2–4dp corners, 1dp borders, status rails on cards, and monospace for every technical value (ticket IDs, site codes, timestamps, KPI figures, the one-hour session countdown); (4) a panel-LED language for live states, including the PRD's blinking 'first job' tag (F-4a). Role branding follows PRD §4.2 exactly: reporter = blueprint blue 'My reports', technician = hi-vis orange 'My jobs' with bottom bar Dashboard·Offers·To report, FM = site teal 'Building overview' with the adaptive split screen (compact vertical split with draggable divider and keyboard collapse, medium 50/50, expanded 60/40 with room for the detail pane). Role UX: the reporter gets a two-action tool with plain-language statuses (R-4) and a durable outbox; the technician gets explicit offer accept/decline with confirmations, REWORK reasons surfaced, and the locked-prefill report template (T-5); the FM gets tappable KPI tiles filtering the 'Needs you' queue, one-tap guarded decisions with mandatory reasons (F-2a), dashboard→chat hand-off (F-6) and explicit confirmation cards for agent-proposed actions (F-7). Implementation: Kotlin Multiplatform + Compose Multiplatform, Android-first per PRD Q5/§11, with a CbmApi interface mirroring the /v1 endpoints and a FakeCbmApi demo implementation to be swapped for the HTTPS client.
